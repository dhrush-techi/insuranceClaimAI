Your project is a fully integrated, AI-powered medical insurance denial-appeal automation system named Lighthouse AI, designed as a full-stack application consisting of a TypeScript/React frontend, a Supabase authentication and user management backend, and a Python FastAPI multi-agent medical/insurance reasoning engine that processes denial letters, medical records, generates evidence-based appeal letters, and provides interactive chatbot explanations with traceability. The system starts with user authentication through Supabase, where each user has an isolated workspace ensured by row-level security so no user can access another’s medical documents or appeal outputs; after login, the user lands on a beautifully styled teal-theme dashboard containing an upload panel, chat interface, history tracker, appeal generator, and analytics links. When a user uploads a denial letter or medical record (PDF, DOCX, or images), the backend begins a 10-phase multi-agent AIML pipeline: Phase 1 performs OCR and text normalization; Phase 2 runs the Analyzer Agent, extracting insurer name, CARC denial codes, denial category (Medical Necessity, Prior Authorization, Coding Error, Administrative), and verbatim denial reasoning; Phase 3 runs the Investigator Agent, which parses medical records to extract clinical severity, failed therapies, symptom progression, coding evidence, authorization references, and risk indicators using span-indexed evidence items with start/end character positions for traceable highlighting; Phase 4 passes results into the Evidence Accumulator, which groups evidence by type, compresses redundancy, computes coverage depth, produces a summary, and populates a structured JSON evidence graph; Phase 5 runs the Traceability Engine, constructing a per-case Appeal Knowledge Graph linking Denial → Evidence → Reasoning → Template → Appeal Output so your system supports transparent AI decisions; Phase 6 performs Confidence Calibration, using heuristic, statistical, and rule-based scoring to assign a confidence score (0–100%) determining whether the appeal can be auto-drafted or requires manual review; Phase 7 invokes the Reasoning Engine, a legal-logic agent that compares denial reasons with extracted clinical evidence to produce a narrative, highlight logical contradictions in insurer reasoning, and determine appeal viability (AUTO_DRAFT / NEEDS_REVIEW / INCOMPLETE_DOCUMENTATION); Phase 8 runs the Adaptive Template Selector, dynamically choosing the best appeal-letter template based on denial type, evidence richness, clinical support, and insurer conventions; Phase 9 triggers the Advocate Agent, which composes a legally-structured, medically-supported formal appeal letter summarizing denial category, quoting insurer reasoning, presenting extracted evidence, and constructing a persuasive argument referencing clinical notes, dates, severity markers and failed therapies using a regulatory-aware tone with built-in fairness guardrails; Phase 10 logs the entire structured result into storage alongside raw texts, extracted snippets, reasoning summaries, appeal drafts, confidence scores, and traceability artifacts, ensuring long-term reusability for analytics. The system also includes a chatbot agent that answers user questions using ONLY their document store; it analyzes case history, medical findings, denial logic, evidence span matches, and reasoning outcomes to accurately respond to queries such as “Why was my claim denied?”, “What evidence supports my appeal?”, “What is my success chance?”, and “Are there coding or authorization issues?”. The chatbot uses a hybrid retrieval approach: denial-text semantic scanning for coding or denial clauses, medical-text retrieval for clinical evidence, and reasoning engine outputs for meta-analysis, ensuring personalized and document-grounded responses rather than generic ones. The dashboard includes a Template Selection module where users can download the appeal letter in PDF, DOCX, or TXT formats generated dynamically by Python modules using python-docx and ReportLab. For analytics and research transparency, your system includes a dedicated Evaluation Metrics Module, which aggregates data from all processed cases (across users) to compute end-to-end AI pipeline metrics such as OCR accuracy, evidence extraction recall/precision, denial classification accuracy, confidence calibration drift, evidence coverage ratio, and template success correlation; the backend exposes this through a /api/evaluate endpoint which runs evaluations across the analyzer, investigator, reasoner, and advocate modules and returns plots/matrices (built using matplotlib and numpy) and computed metrics (JSON) for your React frontend to visualize in the evaluation.ts page. This evaluation dashboard gives insights such as class distributions of denial categories, heatmaps of evidence types vs. confidence score, distribution of denial codes, model error analysis, traceability coverage, and improvement charts comparing old pipeline behavior vs. your novel multi-agent pipeline. Novel scientific contributions making your system research-paper and patent-worthy include: (1) a modular multi-agent, multi-phase pipeline, replacing black-box LLM calls with explicit analyzers, investigators, reasoners, advocates, and calibrators; (2) creation of a per-user Appeal Case Graph that models the lifecycle of claims, evidence, reasoning, and appeals; (3) Span-indexed evidence extraction enabling highlightable traceability in chatbot explanations and letters; (4) Confidence-guided adaptive drafting, deciding auto-draft vs. manual review based on calibrated scores; (5) What-If Simulation, predicting how additional documents or stronger evidence would change the appeal’s confidence score; (6) Active Learning Feedback Loop, where user corrections refine future scoring weights and evidence selection; (7) Fairness and Compliance Guardrails ensuring medically accurate, non-aggressive, policy-conformant appeal generation; and (8) a complete analytics and evaluation framework enabling measurement of improvement over prior versions or baseline heuristics. Your frontend is built with React + TypeScript + Vite, using a custom teal-based UI theme you designed, and includes pages for Home, Auth, Dashboard, Email Confirmation, and Evaluation Metrics. The backend is built with FastAPI and structured into modules for OCR, Analyzer, Investigator, Accumulator, Reasoning Engine, Confidence Calibration, Template Selector, Advocate, Pattern Miner (offline mining of recurring denial patterns), and Traceability, each with transparent JSON interfaces. All data—uploaded files, extracted texts, reasoning outputs, chat messages, appeal drafts, evidence graphs—is stored per user with complete isolation. In summary, Lighthouse AI is a novel AI-powered medical insurance decision-support system that automates appeal generation, enables transparent and traceable medical evidence reasoning, supports user-interactive chat intelligence, and provides research-ready analytics, making it suitable for IEEE publication, academic research papers, and patent filings.
